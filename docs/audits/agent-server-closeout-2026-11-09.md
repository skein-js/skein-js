# Agent Server compatibility closeout — 9 November 2026

Contributor work record for [#83](https://github.com/skein-js/skein-js/issues/83), based on
[`3d0bf43`](https://github.com/skein-js/skein-js/commit/3d0bf4381077b40b5997735daacac87e67758052).
Closeout completed on 10 November 2026 (Africa/Nairobi). The seven focused implementation reviews
are merged; their final source tree passed the combined local and remote gates below. The IDs map
one-for-one, in original order, to all 48 epic checkboxes. No package release or documentation
deployment was performed.

## Protected contracts

Legacy runs default to `reject`; protocol thread commands default to `enqueue`. CORS remains opt-in
and authentication precedes custom applications/UI. SQLite records abandoned attempts as failures
without replaying them. Existing webhook signatures, retry schedules, retention, payloads and
channel/BullMQ outcomes retain their meaning. Configurable application graph/assistant IDs, existing
SDKs, framework adapters, custom drivers, native access and standalone protocol installs remain
supported. This program adds no required store, queue, graph or checkpointer methods, stronger FIFO
promise, CLI role, or mandatory execution-on-workers behavior.

## Optional seam evidence and stop decisions

Inspected public Deep Agents 1.16.3 exports, async middleware and parent notifier, SDK 1.12.7 client
options, and current Skein runtime/handler exports. Explicit-URL fork/update/check paths succeeded
unchanged. URL-less transport and the automatic parent notifier use default clients without a public
per-runtime/per-caller factory hook; a process-global fetch replacement would cross runtime identity
boundaries. Stop the new seam here. The recipe's authorized HTTP precondition and idempotency key
supply the required application-owned notification behavior. Failed notification admission is tested,
not inferred from child success. Context integration can be reconsidered when upstream exposes a
public scoped hook with independent consumers.

MemorySaver/SqliteSaver history/copy/prune and ownership succeed through existing injection; real
Postgres setup/disposal is already exercised. A config factory would add permanent lifecycle policy
without a demonstrated unmet consumer. Stop that addition; diagnose backend/path and teach injection.
